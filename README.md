# 心愿便签 (wish_notes)

一款基于 Flutter 的心愿记录与管理应用。用户可以记录、分类、筛选自己的心愿, 标记「已实现 / 未实现」; 登录后还可以把心愿保存到云端, 在心愿广场浏览他人的公开心愿并参与评论。

项目地址: https://github.com/Milkyink-Evelyn/wish_notes

## 技术路线

本项目同时实现了大作业的两条基础路线, 并在此基础上做了本地与云端的数据协同:

- **路线一: 本地存储** —— 使用 sqflite 保存心愿数据, 使用 shared_preferences 保存登录 token、记住的账号等轻量配置。
- **路线二: 网络请求** —— 使用 Dio 封装 HTTP 请求, 对接培训提供的后端 API, 完成心愿的增删改查、状态修改、公开心愿与评论。
- **本地与云端协同** —— 心愿支持本地 / 云端 / 智能三种存储模式, 通过脏标记做增量同步, 拉取时按字段合并, 并用墓碑机制处理删除。

## 存储模式与同步设计

这是本项目最核心的部分。应用采用离线优先(Offline-First)的思路: 所有增删改先写本地 SQLite, 界面不依赖网络; 登录后通过下拉刷新触发与云端的双向同步。

### 1. 三种存储模式

| 模式 | 数据位置 | 云端同步 | 退出登录 | 适用场景 |
| --- | --- | --- | --- | --- |
| 本地 `LOCAL` | 仅本地数据库 | 完全不参与 | 保留 | 完全私密、只在这台手机使用 |
| 云端 `CLOUD` | 服务器为准, 本地作为缓存 | 双向同步 | 清掉本地副本 | 多设备使用, 数据跟随账号 |
| 智能 `SMART` | 本地正本 + 云端备份 | 双向同步 | 保留 | 推荐, 离线可用且云端有备份 |

使用规则:

- 存储模式在创建心愿时通过弹窗确认, **创建后不能修改**。本地存储不能设为公开, 需要公开请新建一个心愿。
- 首次从云端导入本地缺失的心愿时, 会弹出选择面板: 支持全选 / 取消全选和逐条勾选, 并可统一选择云端或智能存储; 没有勾选的心愿保持云端存储。
- 退出登录时, 云端存储(`CLOUD`)的本地副本(公开和私有)会被删除, 重新登录后可从云端拉回; 智能、本地、广场缓存、墓碑记录和还没上传成功的心愿都会保留。
- 智能存储的私有心愿退出登录后仍可编辑内容、分类和状态, 修改会标记为待同步, 下次登录同步时推送。

### 2. 数据模型中的关键字段

| 字段 | 作用 |
| --- | --- |
| `local_id` | 本地自增主键, 离线新建时先有它 |
| `server_id` | 云端主键, 上传成功后回填; 为空表示还没上过云 |
| `owner_username` | 数据归属账号, 用于多账号隔离; 游客数据为空 |
| `is_deleted` | 墓碑标记, 删除云端已有数据时先软删除 |
| `is_public_cache` | 广场缓存标记, 区分自己的数据和别人的公开心愿 |
| `content_dirty` | 内容或可见性有未同步的本地修改 |
| `status_dirty` | 状态有未同步的本地修改 |
| `category` | 本地分类, 不参与云端同步 |

### 3. 同步触发与执行顺序

**触发时机**: 登录状态下, 在「我的心愿」列表下拉刷新。未登录会完全跳过云端同步, 避免游客数据被推到云端。

`syncAll` 严格按以下顺序执行:

1. **处理墓碑**: 找出 `is_deleted = 1` 且已有 `server_id` 的记录, 调用云端删除接口; 成功后从本地物理删除, 失败则保留墓碑等下次重试。
2. **推送新建**: 找出 `server_id` 为空、非本地存储、属于当前账号的记录, 调用创建接口, 拿到云端 ID 后回填 `server_id`。
3. **推送内容修改**: 找出 `content_dirty = 1` 的记录, 推送内容和可见性。
4. **推送状态修改**: 找出 `status_dirty = 1` 的记录, 推送状态。
5. **拉取合并**: 调用 `GET /wishes/me`, 按字段合并到本地。
6. **清理僵尸数据**: 本地有 `server_id` 但这次云端列表里不存在的记录, 视为在其他设备上已删除, 从本地物理删除。

任何一步网络失败都不会破坏本地数据: 推送失败保留脏标记, 删除失败保留墓碑, 下次下拉刷新继续重试。

### 4. 增量同步与脏标记

每次编辑只推送真正改过的字段, 不再整条覆盖云端:

- 修改内容或可见性: `content_dirty = 1`
- 切换状态: `status_dirty = 1`
- 修改分类: 只改本地, 不标脏

推送成功后会清掉脏标记, 但清之前会核对当前值和推送时的值是否一致。如果推送期间用户又改了这条心愿, 标记不会被误清, 留到下一次同步继续推送。

拉取合并时遵循「脏字段保留本地, 干净字段接受云端」: 本地改过但还没推上去的字段不会在拉取时被云端旧值覆盖。

数据库版本 4 新增了这两列。从 v3 升级时, 已有 `server_id` 且未删除的智能存储心愿会补标一次脏, 保证升级后本地这份数据先推一次; 云端存储的已同步数据保持干净, 仍以服务器为准。

### 5. 合并规则

| 数据 | 合并规则 |
| --- | --- |
| 内容、可见性 | `content_dirty = 1` 时保留本地, 否则使用云端 |
| 状态 | `status_dirty = 1` 时保留本地, 否则使用云端 |
| 分类 | 后端没有分类字段, 始终保留本地 |
| 评论 | 拉取详情时使用云端评论覆盖本地缓存 |
| 存储模式 | 创建或首次导入时确定, 合并时不会改动 |
| 归属用户名 | 云端有值就用云端的, 没有则保留本地 |
| 广场缓存 | 整体跟随云端刷新, 只保留本地分类 |

### 6. 冲突处理

| 场景 | 处理方式 |
| --- | --- |
| 本地有未同步修改, 云端也有新值 | 先把本地脏字段推上去再拉取, 本地修改不会丢 |
| 两台设备修改同一字段 | 以最后推送成功的为准(Last-Writer-Wins) |
| 本地已删除, 云端仍存在 | 墓碑优先, 删除云端记录 |
| 云端已删除, 本地仍存在 | 僵尸清理, 物理删除本地记录 |
| 本地没有, 云端有 | 插入本地, 默认云端存储, 用户可改为智能 |
| 广场缓存与云端不一致 | 用云端数据整体刷新缓存 |
| 推送失败 | 保留脏标记或墓碑, 下次同步重试 |
| 推送过程中用户再次修改 | 清脏前比对当前值, 值变了就不清 |

### 7. 多账号与游客隔离

- 每条真实数据都记录 `owner_username`; 登录后所有查询、推送、拉取都限定为当前账号, 避免串号。
- 游客数据 `owner_username` 为空, 不参与云端同步。游客视角可以看到本机全部账号和游客的数据, 方便在同一台设备上切换查看。
- 未登录时可以正常使用本地和智能存储的私有心愿; 公开心愿的发布、评论、回复需要先登录。

## 已实现功能

### 心愿管理

- 创建、查看、编辑、删除心愿, 支持本地 / 云端 / 智能三种存储模式
- 已实现 / 未实现状态切换
- 五种分类(学习成长、生活日常、旅行探索、兴趣爱好、其他), 支持按分类筛选
- 支持按状态筛选, 默认按创建时间倒序展示
- 表单校验、删除二次确认和操作结果提示
- 空列表、加载中、网络异常均有对应提示

### 本地存储

- sqflite 建库建表, 关闭应用后数据仍然保留
- shared_preferences 保存 token、用户信息、记住的账号
- 未登录也能完整使用本地心愿功能
- 智能存储的私有心愿退出登录后仍可编辑

### 云端与社区

- 注册 / 登录 / 退出登录
- 云端心愿的上传、拉取、更新、删除与状态同步
- 墓碑删除、脏标记增量同步、字段级合并与僵尸数据清理
- 首次从云端导入心愿时可选云端或智能存储, 支持全选和部分选取
- 心愿广场: 浏览公开心愿, 支持全部/未实现/已实现筛选, 按时间或评论数排序, 下拉刷新和本地缓存
- 心愿详情与评论: 发表评论、回复评论、删除自己的评论
- 公开心愿展示作者, 未知作者按数据来源补全或显示为匿名用户

### 交互与视觉

- 启动页、底部导航、自定义弹窗、Toast 提示
- 分类色条、分类图标、卡片状态样式
- 适配常见 Android 手机屏幕, 页面切换和返回逻辑基于 Navigator 1.0

## 已知限制

- 同一字段在多台设备上并发修改时采用后写覆盖, 暂未引入版本号或时间戳仲裁。
- 创建请求如果在服务端已成功但客户端没收到响应, 下次同步可能重复创建一条。
- 本地有未同步修改、但云端列表已经不存在该记录时, 僵尸清理会直接删除本地记录。
- 离线状态下退出登录会清掉云端存储的本地副本, 其中未推送的修改会一起丢失。
